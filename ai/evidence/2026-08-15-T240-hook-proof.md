for a deliberately bad commit **made and discarded**, rather than for the script to be read.
The clone is cloned from the working tree, the gate is copied in, and the whole directory is
removed at the end — the last line of the transcript is that removal.

## What each step establishes

| Step | Establishes |
|---|---|
| 1 | Without the hook the bad commit **succeeds**. Without this the rest could be a repository that rejects everything. |
| 3 | Both defects are caught at once, and **each names its offending line** — the first acceptance criterion. `HEAD` is unmoved. |
| 4 | A missing `Task:` trailer alone is refused. `fb41895` carried both defects; either is enough. |
| 5 | `Task: none - <reason>` is accepted, so §13's *"omit only for work no task covers"* survives. |
| 6 | A conforming message passes. The control for step 3. |
| 7 | `--no-verify` **bypasses the hook**, and the range check then reports what slipped through. This is the trap `T-240` names: the hook prevents and can be skipped; CI reports and cannot. |

## The number in step 7 is not a defect

278 of the 915 commits in this history have no `Task:` trailer, because most of them predate
the requirement. That is why the CI workflow checks **only the pushed range** and never the
whole history: a gate that fails every run for a reason nobody is allowed to fix is a gate that
gets switched off. `12dff92` is excluded by name as well, on `T-065`'s decision.

**Measured on the last 60 commits: 53 carry the trailer and 7 do not** — status syncs and
review records, which is exactly the class §13 permits to omit. Under this gate those now say
so explicitly with `Task: none - <reason>`. The gate therefore changes practice slightly rather
than only enforcing it, and that is recorded here rather than discovered on the first refusal.

## The script

```bash
#!/usr/bin/env bash
# T-240's fourth criterion: prove the gate with a deliberately bad commit, made and discarded in a
# scratch clone rather than by reading the script.
set -uo pipefail
REPO=/mnt/projects/software_projects/tracks-and-trails/tracks-and-trails
SCRATCH="$(mktemp -d -t t240-XXXXXX)"
echo "scratch clone: $SCRATCH"
echo

git clone -q --no-hardlinks "$REPO" "$SCRATCH/clone"
cd "$SCRATCH/clone"
# The working tree of the clone is HEAD; copy in the uncommitted gate so it is what runs.
cp "$REPO/tools/commit_message_check.py" tools/
mkdir -p .githooks
cp "$REPO/.githooks/commit-msg" .githooks/
cp "$REPO/tools/install-hooks.sh" tools/
chmod +x .githooks/commit-msg tools/install-hooks.sh

echo "=== 1. Before installing the hook: a bad commit succeeds ==="
echo "one" > file.txt && git add file.txt
git commit -q -F - <<'MSG'
Add a file with no task and an AI co-author

Nothing should let this through once the hook is installed.

Co-Authored-By: Claude <noreply@anthropic.com>
MSG
echo "exit=$?  -> $(git log --oneline -1)"
echo

echo "=== 2. Install the hook ==="
tools/install-hooks.sh
echo

echo "=== 3. The same bad commit is now refused ==="
echo "two" > file.txt && git add file.txt
git commit -F - <<'MSG'
Add a file with no task and an AI co-author

This is the message that reached origin/main as 12dff92 and again as
fb41895.

Co-Authored-By: Claude <noreply@anthropic.com>
MSG
echo "exit=$?"
echo "HEAD is still: $(git log --oneline -1)"
echo

echo "=== 4. A missing Task: trailer alone is refused ==="
git commit -F - <<'MSG'
Add a file with no task trailer at all

fb41895 omitted this as well as carrying the trailer.
MSG
echo "exit=$?"
echo

echo "=== 5. An explained exemption is accepted ==="
git commit -q -F - <<'MSG'
Add a file no task covers

AGENTS.md §13 permits omitting the trailer for work no task covers, so
the exemption is spelled out rather than left as an absence.

Task: none - scratch-clone proof for T-240, covered by no task
MSG
echo "exit=$?  -> $(git log --oneline -1)"
echo

echo "=== 6. A conforming message is accepted ==="
echo "three" > file.txt && git add file.txt
git commit -q -F - <<'MSG'
Add a third line to the file

The control: without this the proof above could be a hook that refuses
everything.

Task: T-240
MSG
echo "exit=$?  -> $(git log --oneline -1)"
echo

echo "=== 7. --no-verify bypasses it, which is why CI checks the range too ==="
echo "four" > file.txt && git add file.txt
git commit -q --no-verify -F - <<'MSG'
Slip one past the hook

Co-Authored-By: Claude <noreply@anthropic.com>
MSG
echo "exit=$?  -> $(git log --oneline -1)"
echo
echo "--- the range check over everything this clone added ---"
python3 tools/commit_message_check.py --range "$(git rev-list --max-parents=0 HEAD | tail -1)..HEAD" \
  2>&1 | tail -20
echo "range check exit=$?"
echo

cd /
rm -rf "$SCRATCH"
echo "=== scratch clone discarded: $SCRATCH ==="
```
