The content lesson from those two rounds is unchanged and is why the right two columns look empty: things with no dependencies do not belong in a dependency diagram, and the honest way to say so is white space.

T-182 was the sharper of the two rulings waiting on the maintainer, and it was taken on 2026-08-07 (SEC-003). Six yt-dlp option families pointed opposite a written constraint. Ruled: --netrc and client certificates in, -u/-p/--video-password out — the application never holds a secret, which is the same boundary _require_credential_free_proxy already enforces for proxies; --impersonate and --xff out; --geo-verification-proxy in, because a proxy you own is not a header you spoof; --exec out; --download-archive in as a user-named file with no default path; SponsorBlock in, opt-in, with NFR-007 amended to name it. Three turned on a measurement rather than a reading. SponsorBlock sends sha256(video_id)[:4] — one bucket in 65,536 — not a video id. --impersonate is inert without curl_cffi, which is not installed, so permitting it would have added a runtime dependency. And --xff's own option help calls it geographic-restriction bypass. The ruling also corrected ARC-010, which claimed --exec is bound by path containment: it is not, because a shell command writes wherever it likes, and only refusal reaches it.

One ruling is still waiting on the maintainer: T-171, whether downloaded files carry provenance. It is on no critical path, and its measurement is already done.

What to do next, in order

One ordering, and the reason for it. The numbers are a sequence rather than a ranking. Reordered 2026-08-08, and this one is a proposal rather than a transcription — the list is the only part of this board that is not copied out of a file, so it is the only part that can be argued with. The previous version led with T-109 on the grounds that it is the largest item and its blocker had just cleared. That is still true, and it is no longer the best reason to go first.

The argument for changing it is the exit criteria. Four remain; one of those is a signature, and the other three belong to exactly two tasks — T-112 owns criteria 3 and 4, T-113 owns criterion 5. T-109 and T-110 are the phase's two largest items and neither carries an exit criterion at all. Leading with them means spending the phase's biggest budget before touching anything the phase is measured on. This is a sequencing suggestion, not a ruling: nothing in the plan requires it and the maintainer may take these in any order they like. It is written down because the previous order had a reason that has quietly expired, and an order nobody re-argues is how the criteria-bearing work ends up last by accident.

  1. T-113 Resume across a restart Highest uncertainty · exit 5

    First because it is the one item whose cost is unknown, and the cheapest time to find that out is now. It reopens two accepted decisions by design — UX-001's queue-level pause and T-080's removal of JobStatus.PAUSED — and UX-007 gave it a second job: P-10 was ruled to be this task's to decide, so it must record whether per-job pause returns and whether a playlist header gets Pause all, either way. It also carries exit criterion 5, which is written to be satisfiable in two directions — a partial download resumes, or clearly states it cannot — so it cannot fail outright, only expensively. Discovering that late is how a phase overruns.

  2. T-112 Output template editor, with a live preview Two criteria in one task

    The best ratio on the board: medium risk, one settled surface, and it discharges half of what the phase has left to prove — criterion 3, that the preview matches the written path including titles with characters illegal on Windows, and criterion 4, that no rendered template escapes the output directory. T-034 already built and gated containment, so criterion 4 is extending a proof rather than writing one. The risk it does carry is stated in the plan and is worth respecting: preview and real path must be one function. Two functions that agree today is the exact shape of the defect this project keeps finding — computed correctly, then not the thing that was acted on.

  3. T-109 Post-processing, seven options Largest · head of the only chain

    The biggest item in the phase, the head of its only forced sequence, and the one with a documented history of failing quietly: T-077 found four of five Phase 1 options never produced a file. Its blocker really is gone — T-108 settled the ffmpeg-presence rule and proved it on both platforms — so this is a scheduling call rather than a wait. P-17 gave it a second question to answer: where the subtitle language list comes from, since it is now the probe's own languages and SUBTITLE_LANGUAGES is ("all",) today. T-111 follows it directly, because a preset is a named bundle of exactly these options.

  4. T-110 Playlists, properly Structural · reaches core/

    Changes what a job is, so it reaches core/ rather than the UI, and that is the argument for not having it in flight at the same time as anything else on this list. Its surface is settled — the picker is the staging row opened (P-19, the same mechanism P-1 gave the format table) with checkboxes and a tri-state header (P-5). T-143 is its neighbour and arguably its first half: a playlist's entries are never probed today, so their rows stay bare.

  5. T-189 Make a skipped gate fail An hour · CI only, no product source

    Not fifth in importance — fifth because it fits in the gaps between the four above. T-108's only follow-up, and the honest kind: the merged-file test that proves exit criterion 2 skips when ffmpeg is absent, and the self-hosted Windows job records the tool without requiring it. Nothing is wrong today, and ffmpeg 8.1.2 was there when the proof ran. But a later missing install would leave CI green with a required cross-platform proof silently gone — a met criterion quietly becoming an unmet one with nothing to show for it.

T-111 and T-114 are off this list because nothing about their order is contentious. T-111 follows T-109 and cannot sensibly precede it; T-114 is the smallest thing in the phase, depends on nothing, and is a reasonable half-day for anyone who wants a finished task. T-143, T-180 and T-186 are cleanup and belong in the gaps too; T-180 carries the open T179-R3 and is a decision before it is a change. T-188 is open and narrower than it was: T-108's end-to-end test drives a local HLS presentation through real yt-dlp, so the routing is exercised against a real extractor's output on every run — what is still missing is a committed fixture from a public source, because a presentation this project generates does not show that any real site publishes that shape.

The target is capability parity, not flag parity, and the difference is load-bearing. A large share of yt-dlp's surface is the command line — --simulate, --print, --dump-json, --batch-file, the progress and quiet flags, config locations, aliases. This application is the caller of those and already sets several for the worker to function; exposing them would be exposing its own plumbing. So REQ-030 promises that no download reachable from the command line is unreachable from the GUI, and names the exclusions rather than quietly leaving them out. T-183's application-owned list is derived from build_options with a test asserting the two agree, so the refusal list cannot drift from what the code actually sets.

The risk this phase accepts, stated where it can be checked later: the escape hatch becomes the interface. A text field that takes command-line syntax makes every capability reachable and none discoverable, and it would be an easy phase to declare finished with the common options still being typed as flags. ARC-010 accepted that trade knowingly and the mitigation is an exit criterion rather than an intention — promotion of the options users actually type is deliverable work, and the phase does not exit while the common ones are still free text.

Distribution is not renumbered, and that is a choice rather than an oversight. "Phase 5" names the distribution phase in five documents and in every review record that cites it. Renumbering would rewrite the meaning of references nobody can retroactively correct, to buy an integer; 4.5 is uglier and cannot mislead.
