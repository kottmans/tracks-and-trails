Both charts on this board are now drawn by hand, and that is the answer to a complaint this page has earned twice. They were Mermaid until 2026-08-08. Mermaid lays itself out, so when a chart came out too wide or too cramped the only levers were to draw less of it or to shrink it — and this board pulled both, once in each direction on the same day: first a version that wired every independent task through one "head" node, which drew no relationship at all as though it were a bottleneck and ran three times wider than the page; then a correction that cut it to the four-task chain, legible and describing a third of the phase. The width fix at the time was a fit/full-size toggle, which offered the reader a choice between unreadable and sideways — a way of not choosing. Under a drawn figure the grid, the box size and the type size are the page's own, so all nine deliverables and the six loose items fit at 13px with the distinction held in the layout instead of in arrows that do not exist. The content lesson from those two rounds is unchanged and is why the right two columns look empty: things with no dependencies do not belong in a dependency diagram, and the honest way to say so is white space.

T-182 was the sharper of the two rulings waiting on the maintainer, and it was taken on 2026-08-07 (SEC-003). Six yt-dlp option families pointed opposite a written constraint. Ruled: --netrc and client certificates in, -u/-p/--video-password out — the application never holds a secret, which is the same boundary _require_credential_free_proxy already enforces for proxies; --impersonate and --xff out; --geo-verification-proxy in, because a proxy you own is not a header you spoof; --exec out; --download-archive in as a user-named file with no default path; SponsorBlock in, opt-in, with NFR-007 amended to name it. Three turned on a measurement rather than a reading. SponsorBlock sends sha256(video_id)[:4] — one bucket in 65,536 — not a video id. --impersonate is inert without curl_cffi, which is not installed, so permitting it would have added a runtime dependency. And --xff's own option help calls it geographic-restriction bypass. The ruling also corrected ARC-010, which claimed --exec is bound by path containment: it is not, because a shell command writes wherever it likes, and only refusal reaches it.

One ruling is still waiting on the maintainer: T-171, whether downloaded files carry provenance. It is on no critical path, and its measurement is already done.

What comes after: Phase 4.5, and why it exists at all

Added 2026-08-07 between Settings and Distribution. The premise of this application is that it is a GUI for yt-dlp, and it can currently express eleven of yt-dlp's options. Phase 3 and Phase 4 add perhaps fifteen more. The option list runs to roughly 250 across sixteen groups — so the gap is not a rounding error, and shipping a first release without closing it would mean shipping the claim without the thing.

The target is capability parity, not flag parity, and the difference is load-bearing. A large share of yt-dlp's surface is the command line — --simulate, --print, --dump-json, --batch-file, the progress and quiet flags, config locations, aliases. This application is the caller of those and already sets several for the worker to function; exposing them would be exposing its own plumbing. So REQ-030 promises that no download reachable from the command line is unreachable from the GUI, and names the exclusions rather than quietly leaving them out. T-183's application-owned list is derived from build_options with a test asserting the two agree, so the refusal list cannot drift from what the code actually sets.

The risk this phase accepts, stated where it can be checked later: the escape hatch becomes the interface. A text field that takes command-line syntax makes every capability reachable and none discoverable, and it would be an easy phase to declare finished with the common options still being typed as flags. ARC-010 accepted that trade knowingly and the mitigation is an exit criterion rather than an intention — promotion of the options users actually type is deliverable work, and the phase does not exit while the common ones are still free text.

Distribution is not renumbered, and that is a choice rather than an oversight. "Phase 5" names the distribution phase in five documents and in every review record that cites it. Renumbering would rewrite the meaning of references nobody can retroactively correct, to buy an integer; 4.5 is uglier and cannot mislead.
