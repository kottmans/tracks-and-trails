## What this commit adds, and why the existing regression was not enough

The reviewer regression asserts a playlist **offers** an editor and that its header is editable.
**Both would still hold if choosing did nothing at all.** `T140-R3`'s recommendation was to *"make
retargeting honor group inheritance"*, which is a claim about what happens to the members — and
nothing asserted it.

Two tests:

- **`test_choosing_on_the_group_retargets_every_member_that_can_still_move`** — one choice on the
  group emits for `entry-1` and `entry-2` and for neither `entry-0`. `_playlist_jobs` makes the
  first entry `COMPLETED`, so the `RETARGETABLE` exclusion is *exercised* rather than assumed, and
  every member receives the same name.
- **`test_a_finished_playlist_refuses_a_group_retarget`** — a playlist with nothing left to move
  returns `False` and emits nothing. The header already withholds the control, but the delegate is
  not `setData`'s only caller, and a model that answers a write it should refuse is one reset away
  from re-entering itself (`T126-R3`).

## Two submitted uncertainties

**1. `not movable` is redundant.** `all()` over an empty sequence is already `True`, so
`if not movable or all(...)` and `if all(...)` return `False` by the same path. That is why the
third mutant survived: it is equivalent, not evidence of a weak test. **It is left in place** —
removing it is a simplification, and `AGENTS.md` §7 rules out tidying under a review finding. Say
if you would rather it went, and it can be its own change.

**2. The same-value half of the guard is not asserted, deliberately.** `FakeQueue` does not apply a
retarget, so members keep their original request and re-sending a name is a genuine second change.
An assertion there would have passed by measuring the fixture rather than the guard — the shape
`T126-R3` was, and the shape this project keeps finding. Covering it honestly needs members whose
request matches a built-in preset, which is a fixture change rather than a test; it is disclosed
instead of faked.
