## Read this first: two findings that changed the plan

**1. The pane's removal and the row's verbs cannot be separate commits.** `JobProgressView` was the
**only** UI route to *Cancel* and *Retry* — `queue_view.py` had neither, and the toolbar has Pause,
Remove, Move up/down and Clear, none of which stops a download in flight. I had planned to land the
tabs first. That commit would have shipped a window where a user could not cancel a running
download or act on `REQ-018`. The order is therefore verbs → tabs, in one change.

**2. Deleting the pane's tests would have deleted `JobProgressView.detach`'s only coverage.**
`UX-005` *defers* what becomes of that widget rather than deciding it. `detach` appeared **zero**
times in `tests/ui/test_job_detail.py`; its sole test anywhere was
`test_replacing_the_watched_job_leaves_no_second_listener`, a composition test about the pane. So a
view-level test was written and mutation-checked **before** that one was removed. Without it, a
deferral would have become a silent deletion — which is the shape of `P2EXIT-R5` on a different
subject.

Both are recorded in `T-124` rather than only here.

## The decisions inside this change that are worth attacking

**Where the verbs sit.** `UX-005` §4 says the verbs share the row's last line with the format
control. The control currently occupies a fixed full-height right slot — and `UX-005`'s *"what this
does not decide"* explicitly defers that slot to `UX-004`. So the verbs are right-aligned **inside
the text area**, which is already narrowed by the control's slot, putting them immediately left of
it and touching nothing `UX-005` deferred. That is a reading. A different one is defensible.

**Three states `UX-005` does not name.** Its table has Running, Queued, Failed, Done; the pipeline
has eight statuses. `PROBING` and `POST_PROCESSING` are treated as Running (a worker holds the
job), and `CANCELLED` offers only *Remove* (no file, nothing to retry). The module says in as many
words that this is a reading of the entry rather than part of it, and that it deserves an
amendment.

**`⋯` is drawn on every row that has verbs, and only those.** It is the declared keyboard route, so
it is laid out first — rightmost — and does not move as the state changes. It is *not* drawn on a
row with no verbs at all: the add dialog's staging rows have no job behind them, and drawing it
there offered a menu of nothing **and** silently regressed `T118-R8` by narrowing the selector line
whenever a format control was present. That was caught by `T118-R12`'s own test, not by reading.

### The survivor, which was two different mistakes

**First it survived because the test could not tell.** Four of the five built-in presets share a
selector with another — `Audio only (MP3)` and `Audio only (original)` are both `bestaudio/best` —
so selector-only matching returns whichever is defined *first*, and my test had used the first one.
The first entry of a colliding set is the one value that cannot distinguish the two
implementations. Using the second killed it at once.

**Then the re-run also passed** — because `ruff format` had reflowed the target expression onto one
line, so the scripted `str.replace` matched nothing and edited nothing. Two identical false
survivors before I checked. Mutation scripts now assert the edit applied.

Both are written into `ai/TESTING.md` §13 rather than only here, because neither is about this
task.

**Two vacuous tests I wrote were deleted rather than committed** — one was `assert ... or True`, the
other asserted a list stayed empty when nothing could have filled it. They are the exact shapes in
`ai/TESTING.md` §13's table, written by the person who had just written the code, which is that
section's whole thesis. Worth knowing they were there.

## What the tests assert, and why that shape

- **`tests/ui/test_row_verbs.py`** transcribes `UX-005` §4 by hand rather than reading the module's
  literal. `assert verbs_for(s) == _BY_STATUS[s]` would be an identity — `T034-R4`'s failure.
- It asserts the **complement** too: which verbs each state must *never* offer. That is the half
  `T081-R3` says is easy to lose, and the half `UX-005` §5 is actually about.
- **`tests/ui/test_row_verb_wiring.py`** asserts the **destination**, never the signal. `UX-005` §4
  adds a second route to five effects that already had one, and two routes to one effect is how one
  of them ends up with a guard the other lacks. So `_remove_job` and `_move_job` are single
  implementations the toolbar and the row both use, and the file verbs go through `FileActions` so
  `SEC-001`'s containment is not reimplemented.
- The window test asserts **there is no `QSplitter` anywhere in the window**, not merely that a tab
  widget exists — a tab widget added beside a surviving splitter would satisfy the weaker claim and
  leave the rejected layout on screen.

## Assertions parked at the boundary, and where they went

`test_end_to_end` no longer asserts through the pane that a finished job offers no *Cancel*, or
that a recovered job offers *Retry*. Both now live in `tests/ui/test_row_verbs.py`'s forbidden-verb
test and in the composition test's `verbs_of` check, and both places say so. **Neither was
dropped**; check that I actually landed them where the comments claim.

## Also changed

- `tests/integration/test_composition.py`'s signal census: `job_changed` goes 2 → 1, and 3 → 2 with
  the dialog open, because composition no longer claims the pane. The number is still **written
  down rather than counted** — that is the point of the test.
- `shown_status()` helpers in `test_end_to_end` and `test_composition` read the **queue row**, not
  the store. The reason the pane was watched before still applies: `T-013`'s ordering means the
  database leads the UI, so a store-based wait passes in the gap before anything on screen changes.
- Two `IndexError`s I introduced and fixed: `dialog.queued_job_ids[0]` read immediately after
  `add_to_queue()`, which goes through the writer thread. Both now spin first.

## `HistoryView`, since it is the largest single piece

A `QListView` behind `RowDelegate`. `UX-005` §3: "History changes what the fields *say*, not what
they are." Headline the title, detail the size and when, **the saved path on its own last line**,
and the two file verbs — no progress role, because a finished record has no progress and the
delegate draws a bar for anything that answers.

**The six columns survive as what the row says.** `_text` and `COLUMN_HEADERS` are still the single
source of every string, which is what keeps `REQ-020`'s fields named in one place. Two tests were
rewritten rather than deleted: the per-cell accessible text named its column, which is meaningless
with one column, so the row now speaks **every** field and the test asserts them individually
rather than as one sentence; and the per-column tooltips became one tooltip carrying the whole URL
and the whole path, because the need — copying a path into a bug report — did not change.

`tests/ui/test_file_actions.py` used `selectRow`, a `QTableView` method. It selects by index now.
