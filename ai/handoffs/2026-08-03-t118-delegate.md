## `T118-R10` — and the assertion I would check hardest

The old gate measured 0.722 s (red), passed, then 0.520 s (red) on one unchanged path. Replaced by:

1. **An absolute budget with headroom.** `SUPPORTED_PASTE` 150 → **500**; budget **1.0 s** against a
   measured **0.042 s**. A 24x margin, deliberately not the largest number one Linux run will bear.
2. **A ratio**, which does not move with runner speed: four times the paste must cost under six
   times the time. Measured 0.020 s at 125, 0.042 s at 500, 0.047 s at 1000.
3. **A count of the controls that exist.**

**Check the third hardest, because the first two are nearly worthless here and I only found that
out by mutating them.** A mutation restoring a persistent editor per row **passed both timing
tests**. These tests never `show()` the dialog, and an unshown Qt view lays nothing out — so 500
hidden combo boxes are cheap on Linux and ruinous on the platform that measured 0.722 s. The
structural count fails that mutation on any machine, with `500 per-row controls exist for 500 rows`.

I have kept all three. If you think the two timing tests now earn their runtime, say so — my own
view is that (1) is a coarse backstop and (2) is the honest instrument, and neither should be read
as evidence about Windows.

Repaint was measured directly and is **flat in the model**: 12 rows cost 3.1 ms median whether the
model holds 12, 150, 500 or 2000; 40 rows cost 10.2 ms.

## The other thing I would check hardest

**`QueueModel` now answers two vocabularies for one row.** `COLUMN_HEADERS` and `_text` still answer
`REQ-014` per field — that is what `accessible_text_at` reads and what pins the requirement — while
the delegate's roles compose those same cells into the drawn row. I kept the columns deliberately:
deleting the per-field transcription to change a widget would have thrown away the thing the
requirement is pinned by.

The risk is that the two drift. I believe they cannot, because every role branch calls `_text` with
a named column rather than re-rendering, and a test asserts each column's string appears in the
drawn row. But if a path exists that renders a field twice, that test would not see it, and the
symptom would be a screen reader and a sighted user told different things — `T017-R2` exactly.

## What I got wrong, and what caught it

**Four mutations survived their first run. Every one changed the work rather than the record** —
which is the argument for running them at all, since three exposed a test that could not fail for
the reason it named.

1. **Two guards made each other untestable.** A thumbnail URL known to fail was gated in `_begin`
   *and* in `_on_disk_missed`; removing either left the other, so no test could tell whether the
   rule held. One gate now, and the mutation dies.
2. **A fetch count could not see an asynchronous fetch.** Making `peek` start one — the exact
   defect that would make "no fetch for an unpainted row" false whenever anything asked — was
   invisible to a counter that only rises after a thread hop. Added `ThumbnailStore.pending_urls`,
   which answers synchronously.
3. **The progress bar could tell the lie the text was written to avoid.** An unknown total renders
   as `—` in words; only that was asserted, so a bar sitting at 0% would have shipped.
4. **The widget-per-row mutation passing both timing tests**, above.

**And a gate I skipped.** `ai/TESTING.md` §12 says to run **bare** `mypy` whenever a test file
changes, and records `T-016` learning that the expensive way — a handoff that reported `mypy src`
and `mypy --platform win32 src` as passing, both true, while CI failed on two real errors in
`tests/ui/test_add_dialog.py`. I ran the scoped commands and reported them as complete in an earlier
draft of this batch. The unscoped run then found **four** errors in `tests/ui/test_row_delegate.py`:
two Liskov violations from narrowing Qt's index union, and two lambdas mypy could not infer. Fixed
in `797db86`. Nothing reached CI, but only because you asked for this handoff before I pushed.
