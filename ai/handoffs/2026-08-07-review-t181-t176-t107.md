## `T-181` — the queue is stopped until it is started

`UX-006`. Adding a URL enqueues it and starts nothing; `Start` runs the queue and it stays running
until `Stop`; the queue is stopped at **every launch**, so restoring a queue no longer downloads
without the user. `UX-001`'s drain is unchanged, which is why this needed no new mechanism —
`T-080` built the gate and `T080-R1` already made it park a download while admitting a probe.

`pause()`/`resume()`/`is_paused`/`queue_paused` became
`stop_queue()`/`start_queue()`/`is_running`/`queue_running`. The toolbar control's label follows the
state; the status bar carries *Queue stopped — press Start to download*.

### Three things I would put in front of you first

**1. A criterion in the task entry could not be met as written, and I say so rather than claiming
it.** It asked for "a test that fails if the gate check is removed from the retry path". **There is
no such single check.** `_start_when_free` and `start()` both carry the gate and each catches what
the other releases. All three mutants were run: removing either alone leaves the five gate tests
green; removing **both** fails the retry test. Neither guard is individually load-bearing. The
test's docstring records this, because my first version claimed the single-point mutation worked and
the measurement disproved it.

**2. `active_job_ids()` cannot express "nothing started"**, and two of my tests were written against
it before I noticed. It counts *waiting* jobs as active by design (`T078-R1`), so a correctly parked
job makes it non-empty — the tests failed against correct code. They assert on `_sessions` and the
durable status now.

**3. A retried *probe* is exempt from the gate, correctly**, because a `QUEUED` job's session is a
probe (`ARC-004`). My first retry test started from `QUEUED`, watched the retry run, and would have
reported a correct exemption as a defect. It starts from `READY`.

### What I did not build, deliberately

`docs/UX_SPEC.md` §2 item 7 says a waiting row reads **Held**. It does not, and did not before this
task either. The stopped state is said **once, at queue level**, in the status bar: writing it into
per-row status text would put a queue-level fact in as many places as there are jobs, which is what
`UX-001` exists to prevent. §2.1 records the choice and flags that clause as worth re-deciding — it
is marked `[T]`, so nothing currently lists it as open. **If you think that reasoning is wrong, this
is the place to say so**, because the clause is spec and I have left it contradicting the build.

### The test-harness change you will notice

`tests/integration/test_manager.py`'s `manager` fixture now presses Start by default and takes
`running=False` for the tests that are about the gate. That default is **deliberately the opposite
of the product's**, and
`test_a_manager_starts_stopped_and_runs_nothing_until_it_is_started` builds a manager directly so
the shipped default is asserted by something the fixture cannot mask. 91 direct constructions across
the suite gained a `start_queue()` line; all mechanical.

**Four of them were not mechanical and are worth checking**: embedded subprocess scripts in
`test_manager.py` (two), `test_end_to_end.py`'s `DOWNLOAD_AND_WAIT`, and
`tests/network/test_real_download.py`. An AST sweep cannot see inside a string literal, and a
stopped queue never spawns the worker those scripts wait for — the parent hung.

## `T-107` — the format table

`FormatInfo` gains `fps` and `bitrate_kbps`: **two columns `REQ-003` has named since it was written,
with nothing to carry them.** **No migration** — nothing persists a `FormatInfo`, which was the risk
I checked before starting rather than during.

### The one criterion I am not claiming

**Phase 3's exit criterion 1 is not met.** The recorded captures carry no `fps`, `tbr`, `vcodec` or
`acodec` — `SEC-002` commits only the fields the projection reads, and it did not read them until
this task — so four of nine columns are evidenced by a **derived** fixture
(`derived_format_columns.json`, declared as derived with `what_is_synthetic`, following
`derived_drm_protected`'s precedent).

**A fixture this project wrote cannot show the table agrees with `yt-dlp -F`.** `T-185` is filed for
the re-capture and owns that criterion's evidence. It needs the network, and `capture.py` is
explicitly run by hand, so I did not run it unasked.

### Two implementation points to check

**Sorting is implemented on the model, and that is not incidental.**
`QTableView.setSortingEnabled(True)` calls `model.sort()`; `QAbstractItemModel`'s default does
nothing. A table that merely enables sorting moves its indicator and leaves the rows alone — worse
than no sorting, because it looks like it worked.
`test_the_table_opens_sorted_by_resolution_best_first` fails if the model stops implementing it.

**Sort keys are always a `(number, text)` pair.** Format ids are `137` *and* `hls-480` in one
column, and a key returning `int` for one row and `str` for another raises `TypeError` the moment
`sorted` compares them. `test_sorting_a_column_of_mixed_ids_does_not_raise` holds it.

### The static boundary check, and why it is narrower than it looks

`test_no_ui_module_reads_a_raw_info_dict_key` asserts `NFR-008` structurally, as `T-097` does for
settings. **Its first version failed on `main_window.py` reading `width`/`height` — which is window
geometry, not an info dict.** A gate that blocks correct code gets deleted, so it now names only
keys that are unambiguously yt-dlp's and documents why `width`, `height`, `ext` and `filesize` are
excluded. **That exclusion is a judgement worth challenging** — it trades some coverage for not
crying wolf.

### What `T-107` did not do

Wiring the table into the staging row. `P-1` ruled *where* it opens; making a chosen format mean
something is `T-108`'s, and this task's scope excludes selection. The widget exposes
`format_chosen` as the seam `T-108` consumes.
