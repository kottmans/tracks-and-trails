## What this round is: I fixed R13's symptom and left its cause

Worth stating first because it is the pattern you have now caught three times, in three different
disguises. Round two moved the block out of `close()` and then **wrote a docstring asserting the
rest was fine** — that `QThreadPool`'s destructor "runs when this store is destroyed — after its
parent has let it go, rather than on the interaction."

That sentence was the defect. The pool was the store's **child**, so deleting the store ran the
destructor *on the GUI thread*; you measured 1.008 s. And every runnable emitted through the store,
which a Python reference does not keep alive on the C++ side, so `_ReadFromDisk` raised
`RuntimeError: Signal source has been deleted`. I had reasoned about ownership in prose instead of
arranging it, and then tested the half I had reasoned about.

**Both are fixed at the root rather than by a shorter wait:**

- The pool is **module-level and shared**. No store's destruction runs it, and the application's
  two stores — the queue's and the dialog's — now share one bound, which they should have anyway.
- Tasks emit through **`_Sink`**, a parentless `QObject` the runnables themselves keep alive. Qt
  severs the store's connections when the store dies, so a late emission goes nowhere rather than
  into freed memory. Nothing in a runnable touches the store.

`ThumbnailStore.pool` is public for one reason: so the regression can block *whichever* pool is in
use rather than the one it expects. See below — that is not incidental.

## `T118-R14` — the previous correction created it

Resetting the model for every value change orphaned any open row editor. Your reading is right and
the trigger is ordinary, not teardown: a sibling row finishing its probe calls `_refresh()` while
someone is choosing a format, and the choice is discarded silently.

`StagingModel.refresh()` now compares row **identity** — `Row` is `eq=False` for `REQ-001`, so
tuple equality is object equality — and emits `dataChanged` when only values moved. A reset is
reserved for the set of rows changing, and `commit_open_editor()` closes the editor first, while
its index is still valid. `_refresh` restores the current row by identity, not by row number.
