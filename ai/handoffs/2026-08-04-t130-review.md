## The three implementations, and the risk in each

**1. `Add URLs` is the menu's `QAction`, not a copy.** `T-016` disables it, with an explanatory
status tip, when composition supplied no job sink or output directory. Two actions would be two
places for that to keep being true, and the first time they diverged a user would get a button that
opens a dialog with nothing behind it.

**2. The chip is the model's to ask for.** New `STATE_CHIP_ROLE`; `QueueModel` answers `True`,
`HistoryModel` answers nothing at all — absent means no, the same shape `T126-R4` established for
`PRESET_INHERITABLE_ROLE`. When the chip is drawn the state is **not** repeated on the second line,
which is where `NFR-006` puts the extractor's message.

> **Superseded by `T130-R3`'s third pass.** The role now carries the chip's *text*, and the second
> line keeps the state unless the chip says exactly it. The sentence above is the reasoning that
> deleted the worker stage from the row — left here because it is what the finding is about.

**3. The selection changed in two places at once, and that is the whole risk.** `RowDelegate` reads
`palette.highlightedText()` for a selected row. Change the style sheet alone and a selected title
draws in white on a near-white tint. Both moved together, and the test asserts the palette
explicitly for that reason. Contrast: **15.55:1 light, 10.81:1 dark**, and the pair is now in
`TEXT_PAIRS` so it cannot quietly regress.

## What a reviewer should attack

1. **The chip's colour was deliberately not taken from the mockup.** The mock colours it per state
   — gold running, red failed. The delegate has the state's *words*, not its status, so a colour
   needs a second role carrying semantics into the place `NFR-005` is hardest to police. Is
   monochrome-plus-words the right call, or is this under-delivering the ruling?
2. **`QListView::item:selected { border-left }`** puts the inset bar on every item view in the
   application, not only the two lists. Check nothing else inherits it badly.
3. **The chip test is a pixel comparison** with one role silenced. It proves the chip is drawn and
   that it changes the row; it does **not** prove the title is elided rather than overdrawn. I
   could not find a cheap assertion for the latter and said so rather than implying coverage.
4. **`T124-R3`'s regression was rewritten, not just repaired.** It asserted the toolbar held
   exactly Pause and Clear; adding `Add URLs` broke it. It now asserts *no toolbar action changes
   with the selection*, which I believe is the property `UX-005` actually chose — but it is a
   different claim from the one the reviewer approved, and worth checking rather than assuming.

## `T130-R1` — High. Correct, and my test had encoded the defect

The ruling wanted a quiet row. I applied it through `QPalette.Highlight`, which is
application-wide — and a row can afford a subtle tint only because it also gets an inset bar.
**Selected text has no second signal.** Measured 1.14:1 light, 1.33:1 dark.

*Corrected by scope*: the sheet tints `QListView, QTreeView, QTableView`, Qt propagates that into
those widgets' palettes, and the application palette keeps the brand highlight.

| | |
|---|---|
| List row, from `option.palette` | tint, **15.55:1** |
| Editor selection | brand, **7.64:1** (floor 3.0) |

**My own regression asserted the *global* palette held the tint.** It encoded the defect, which is
exactly why it kept passing while a selected URL was unreadable. Rewritten to assert both
directions, with that history in its docstring.

## `T130-R3` — Medium. **Wrong. Reopened, and corrected again in a third pass**

*(The paragraph that stood here claimed the stage stayed on the second line. It did not. Left
struck rather than deleted, because the claim is the finding.)*

Deriving the chip from `PROGRESS_ROLE` in the delegate broke two things, both of which the reviewer
found and both of which I verified before touching anything:

| | |
|---|---|
| `row_delegate.py:531` overwrote `state`; `:561` read `second = detail if chipped` | `Downloading video` was on **neither** line |
| `QueueModel._fraction` returns `1.0` for `COMPLETED` **before** consulting totals | every finished row read `100%`, not `Done` |

I also checked whether a paused job would hide behind a percentage. There is no `PAUSED` status, so
it cannot; `FAILED`, `CANCELLED`, `QUEUED` and `PROBING` all return `None` and already chipped
their word. It is exactly the two that were found.

**Corrected at the model, not the delegate.** `STATE_CHIP_ROLE` carries the chip's *text*;
`QueueModel._chip` returns a percentage while `RUNNING` and the compact `CHIP_TEXT` word otherwise.
The delegate draws what it is given and no longer touches `state`, so the erasure is gone
structurally rather than patched.

**Why not the delegate, which would have left your regressions untouched:** `UX-005` names a
vocabulary — `Done`, `Queued`, `62%`, `Failed` — that is *not* `STATUS_TEXT`, which says `Completed`
and `Ready to download`. In the delegate, `Done` is a hardcoded string and terminality is inferred
from `fraction == 1.0`, so a failed job reporting 1.0 would be labelled **Done**. The model knows
the `JobStatus`. The maintainer chose this shape on 2026-08-04 with that trade-off stated.

Verified against a real model rather than asserted:

| status | chip | second line |
|---|---|---|
| `RUNNING` | `62%` | `… — Downloading` |
| `POST_PROCESSING` | `Processing` | `… — Post-processing` |
| `COMPLETED` | `Done` | `… — Completed` |
| `QUEUED` / `FAILED` | `Queued` / `Failed` | word dropped — the chip says exactly it |

Mutations, all killed: model chips a percentage regardless of status → the completed and queued
cases fail; chip takes the stage off line 2 unconditionally → the erasure regression fails;
delegate re-derives the chip from `PROGRESS_ROLE` → the `Done` regression fails.

### Your two replacement regressions passed vacuously, and I did not leave them that way

They supply `STATE_CHIP_ROLE: True`. With the role carrying text the delegate finds no string,
draws no chip, and both compared crops match **because nothing is in them** — `test_row_delegate.py`
went green at 23 passed with the fix in place and would have gone green without it. That is
`ai/TESTING.md` §13 exactly, and the third assertion this session to measure a proxy instead of the
property.

Amended on the maintainer's instruction, and each now fails against the defect it names:

- the erasure test supplies `"62%"` as the chip text, so the two stages differ only where they
  should — chip identical, rows different;
- the terminal test holds **one chip text against two fractions**, which is the delegate's half of
  the finding: progress must not leak into the chip;
- `test_the_state_chip_reads_progress_only_while_a_job_is_actually_running` is new and holds the
  vocabulary at the model, where it now lives. Every row in it carries the **same bytes** and only
  the status moves, which is the distinction the defect collapsed. `Done` is a literal there, not a
  `CHIP_TEXT` lookup, because the word is the ruling.

### One thing I did not change, and you should rule on it

A running row now shows `62%` in the chip **and** `62% · 620 B of 1000 B` on the second line, because
`_detail` leads with the percentage for the `REQ-014` progress column. The mockup's sub-line has no
percentage — the chip carries it. I left `_detail` alone: it is shared with the table's column, the
budget is a third pass on a Medium, and widening the diff to chase a cosmetic redundancy you did
not raise seemed the wrong call. Flagging rather than silently deciding.

## `T130-R2` — Medium. Fixed via `iconText`; the assertion was amended on maintainer instruction

`QToolButton` renders `iconText()` in preference to `text()`, so one `QAction` reads
**"+ Add URLs"** on the toolbar and **"Add URLs..."** in the File menu — `T-016` chose that suffix
for the Windows "opens a dialog" convention, and the amendment adopted a *toolbar* button rather
than a menu label. Putting the `+` in the menu was the alternative and nobody ruled on it.

Measured on the real window: rendered label **and** accessible name both read "+ Add URLs".

**The assertion read `QAction.text()`**, which is not what the toolbar renders. Amended on the
maintainer's instruction of 2026-08-04 to read `bar.widgetForAction(...).text()`, and
**strengthened** while there: it now also pins the announced name, which is the `NFR-005` risk the
`iconText` route introduces and which nothing previously guarded.

*Flagged rather than done quietly: rewriting a reviewer's regression to pass is not the
implementer's to decide. It was decided.*
