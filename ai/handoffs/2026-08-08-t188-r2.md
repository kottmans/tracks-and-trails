## §4 · A methodology failure that invalidated a reported result

**You should know this because it means a result in my last handoff was not sound when I reported
it**, though it holds now.

After the mutation check for `T-188`, restoring the source did not take effect. CPython invalidates
a `.pyc` by comparing the source mtime it recorded against the current one, at **one-second
granularity** — and my restore landed 0.146 s after the cache was written from the mutated source.
Same second, so Python kept the **mutated bytecode** against correct source on disk. The full suite
then reported **23 failures** that had nothing to do with any committed code, and
`_as_stream_presence` returned `True` for `"none"` while the file plainly read
`return codec != "none"`.

**Re-run cleanly** — cache cleared, `PYTHONDONTWRITEBYTECODE=1` — and the result is the one I
reported: **13 caught with the mutation, 22 passing restored.** So the conclusion stands and the
evidence for it did not, until now.

`inspect.getsource` is not a check for this: it reads the file, not the loaded code object. Asking
the imported function what it *returns* is.
