## `T-185` — and `OPS-013`'s gap closed itself

**The `fps` source exists after all.** `peertube_big_buck_bunny_60fps` — the Blender Foundation's own
PeerTube instance, CC BY 3.0, plain object-storage URLs with no query string.

**The eighth attempt worked because it asked a different question.** The seven probes recorded in
the evidence artifact were all *sources*. This one grepped **yt-dlp's own extractor modules for
`fps`** and then looked for a freely licensed instance of a matching extractor. `peertube.py` reads
`fps` from each published file; `archiveorg.py` matches only inside `YoutubeWebArchive`'s itag
table, which is why archive.org itself never reports it. That method is the reusable part.

**The item was chosen for its framerates, not its title.** It reports **30 fps for its 240p–480p
renditions and 60 for its 720p and 1080p**. A source reporting one framerate everywhere would have
filled the column without ever ordering it, and `REQ-003` asks for a *sortable* table — so
`test_fps_comes_from_a_recorded_capture_by_value` sorts it both ways. Three further shapes come
free: height-with-no-width resolutions, exact `filesize`s (against `wikimedia_caminandes`'s
estimates, so both halves of `T107-R7` now rest on recordings), and `unknown` codecs beside known
framerates.

**Worth saying plainly: `OPS-013` is why this happened.** It permitted the gap *only while an open
task owned it*, and the open task is what produced the eighth attempt. A ruling that had simply
excused the column would have left it excused.

### `T107-R8`, and the mutation that found the test could not fail

The literal is gone. `Source` takes `extractor` **keyword-only and required**, so a new source
cannot inherit another's provenance by omission — your "gate a second extractor", as a `TypeError`
at the point the source is written. `capture_info` additionally **refuses to write** when yt-dlp's
own `info["extractor"]` disagrees, so the committed value is hand-written (`SEC-002`'s line intact)
and cannot be false.

**Then the mutation survived.** Re-hardcoding `"archive.org"` passed the entire suite: the
committed-fixture assertion compares files on disk against the declarations, and a broken *writer*
changes no file until somebody re-captures. So the test that caught the original defect could not
catch it coming back. `provenance` is now split out of `capture_info` and tested directly — no
network — and re-running the mutation fails it. **Please check that separation is the right shape**;
it exists to make the gate real rather than because the module wanted refactoring.

Only `wikimedia_caminandes.json` was re-captured. The other three were already correct and churning
their dates would say something changed when nothing did.

## `T-108` — and the widening `T107-R1` deferred

**`REQ-008` cannot decline to classify, and the projection could not classify.** `P-2` routes a row
into *"whichever of the two slots its own kind matches"*, and `_as_optional_codec` maps yt-dlp's
explicit `vcodec: 'none'` **and** a missing key to the same `None`. `T107-R1` is what reading it
anyway cost; `format_table.describe_resolution` names this widening as the thing it was waiting for.

`FormatInfo` gains `has_video`/`has_audio` as **tri-state** — `True` / `False` / `None` for *nobody
said* — projected in the adapter, the only place the difference is still visible (`NFR-008`).
`is_audio_only` is now `has_video is False and has_audio is True`, which is **narrower than before**:
a format nobody classified is no longer audio-only. `is_video_only` joins it. A format naming a
codec for a stream it says it lacks is refused at construction.

**Most formats from most sources come out `UNKNOWN`.** archive.org, PeerTube and Wikimedia all
publish complete files, so the merge mode is not drawn for them — with **its own sentence**,
separate from ffmpeg's, because telling a user to install ffmpeg for a source that would not merge
anyway is advice that cannot help. That second reason is **derived from `UX-005` §5**, not ruled;
`P-13` covers only the ffmpeg case. Flagging it as the place a reviewer may disagree.

### The two ffmpeg facts, kept apart

1. **`merge_refusal`** asks whether the user *stated* a merge — both slots filled — and nothing
   else. It reads no selector, so it cannot repeat `T-061`.
2. **The worker's `_ffmpeg_gap`** is unchanged and remains definitive.

`Row.format_selection` stores the statement beside the selector it produced, because recovering
*"the user chose two streams"* from `137+140` means scanning for a `+` — which is `T-061` arriving
by the front door. `test_a_single_choice_still_queues_without_ffmpeg` deliberately chooses `137`,
one half of the pair, so a check that had drifted into scanning ids has something to catch on.

### The defect the tests found

**`choose_current` emitted `format_chosen` before `selection_changed`.** The dialog closes the panel
on the first and writes the choice on the second, so closing tore the panel off its row, the write
found nothing to write to, and **the chosen format was silently discarded while the row kept its
old one**. Four dialog tests failed on one root cause. The order is now pinned by a test of its own,
and the reason is in the code rather than only here.

### Two Qt mounting details worth your eye

- **`setIndexWidget` defers geometry to the next paint.** The panel kept its own minimum —
  **190×26 inside a row whose `visualRect` was already 485×366** — so the table came out zero pixels
  tall. That is `T107-R2`'s collapse arriving from the *mounting* side, which the widget's own
  layout contract cannot prevent. The panel's first geometry is now set explicitly; Qt keeps
  ownership afterwards.
- **`setUniformItemSizes` is withdrawn while a row is open** and restored after. Left on, Qt draws
  every row at the open one's height. Asserted with a second row present, because with one row the
  two behaviours are indistinguishable.

**The opened row hides its own painted anatomy**, since an index widget covers its item. The panel's
summary line therefore calls `row_text` — the same function the delegate's roles are composed from —
rather than writing that sentence a second time (`T118-R8`). The thumbnail and the format control
are deliberately not reproduced.

## What is new and open: `T-188`

**No acceptable source publishes a video-only and an audio-only format in one item**, so `REQ-008`'s
pair is exercised by `derived_format_columns`, which declares it in `what_is_synthetic`.
`media.ccc.de` has the shape — `vcodec: 'none'` beside a named `acodec`, and `'h264'` with no
`acodec` for its video recordings — and is **not committed**: its API states no licence for any
event of any conference sampled (0 of 222 for 38c3), and `ai/TESTING.md` §5 asks for freely
licensed, not for widely believed to be. That is `OPS-013`'s condition being met rather than
sidestepped: declared synthetic, and owned by an open task.

Its real shape did earn a place in the derived fixture, though — see the mutations below.
