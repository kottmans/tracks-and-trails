### Boundary assessment

The session wrapper covers probes as well as downloads, so format checking cannot bypass it.
It guards each real input, appends policy after extractor input options, and starts ffmpeg with
proxy environment variables removed. Its private method and Popen substitutions are restored
in `finally`; the pinned-method digest makes source changes visible at update time. Refusing an
unsafe format test as a failed format, rather than cancelling the whole item, preserves fallback
selection. External downloader arguments remain refused by SEC-004 and cannot override the guard.

The one-file protocol/demuxer restriction and TLS checks close the measured address, SOCKS and
unchecked-certificate paths. Plain HTTP gets no unsupported TLS option and follows no redirect;
HTTPS redirects are limited by the shared per-link route rule. R1 is a distinct input-composition
hole in this implementation, so the overall boundary remains unapproved.

The maintainer has now explicitly approved temporary fail-closed refusal. Filed **T-370** for
restoration, with native acquisition followed by local cutting/cropping as a candidate to measure,
not an already proven design. **T-369** retains ownership of Windows trust-root measurements;
certificate validation and safe cancellation remain required meanwhile.

Stdin passthrough says only that ffmpeg's own input is a pipe. The upstream WebSocket supplier
is a separate acquisition surface: its pinned call does not explicitly carry these network
settings, and the optional websockets dependency is absent from the reviewed environment.
No real WebSocket route result is claimed. T-370's transport inventory must check suppliers as
well as consumers before adopting them; this review does not certify that separate downloader.

### Transport and capability judgment

`defined_for` locates the same executable as the pinned downloader and caches its option set per
binary for the session. Missing binaries or failed help listings cannot authorize a media read.
The length client asks its actual adjacent ffprobe and reuses its answer across candidate links.
The negative controls check the production clients, so the conditional integration expectations
are not merely a shared-helper assertion that the helper agrees with itself.

On a uniform route, plain HTTP redirects work again while HTTPS upgrades are barred by the
protocol whitelist. When proxy policy can change by host/scheme, the redirect limit is still
required; on Ubuntu 6.1.1 those operations are safely refused. `no_proxy` without any effective
proxy leaves all routes direct and does not cause unnecessary refusal. Debian 5.1.9 refuses
selected-address operations because it lacks the required bind option. Each refusal explains
that a newer ffmpeg may work; no unchecked/direct retry was added.

These are temporary capability limits, now explicit in T-370. The Windows packaging pin is
9.0.2, while the Implementer's targeted native execution used 8.1.2. The capability check applies
to whichever binary the user selects, including a Windows override; the bundled default does
not establish behavior for every alternative build. No Windows Reviewer runtime is claimed.
