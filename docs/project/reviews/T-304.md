### Findings

| ID | Severity | Blocks approval | Finding and evidence | Disposition/status |

| T304-R1 | Medium | Yes | `ui/format_table.py:1015`, `SortableHeader.paintSection`, tests only `hasFocus()` and the current section before painting its two-pixel ring. It never reads `focusRing`. Clicking a real format-table header focuses it with `focusRing=False`, yet paints **430 accent pixels in both themes**, exactly the same ring as after a key press. Thus the task's keyboard-only rule does not cover the custom header painter. | Open; Implementer, current T-304 correction: apply the same input policy to custom-painted focus, ensure the header viewport repaints on handover, and add pointer/keyboard rendering coverage in both themes. This is a narrow observable correctness gap: stylesheet-driven controls work, and
keyboard visibility is preserved, but a normal pointer action on format headers keeps
the distracting ring the ruling removes. Medium severity reflects that limited scope;
it blocks because UX-016 explicitly governs when the ring is drawn. It is not a request
to reverse the accepted keyboard-only design.

### Reproduction and controls

The reviewer built a real `FormatTable` from the committed
`derived_format_columns` capture, dressed the application through `theme.apply`,
and clicked the center of header section 0 using `QTest.mouseClick(header.viewport(),
LeftButton, pos=...)`. Positive controls asserted `header.hasFocus()` and
`header.property('focusRing') is False`. Rendering the header and counting the
applied theme's accent pixels gave:

| Palette | After pointer click | After Shift on the same header | Expected pointer result |
|---|---:|---:|---:|
| Light | 430 | 430 | 0 |
| Dark | 430 | 430 | 0 |

The fixed-input scratch regression failed **2 of 2 cases in 0.34s** on exact-head
source. As a diagnostic control only, requiring `self.property(theme.FOCUS_RING_PROPERTY)
is True` in that painter's existing condition changed the renders to **0 after click,
430 after key**, in both themes: **2 passed in 0.50s**. That control changed only a
temporary archived source file, asserted its replacement applied, cleared bytecode
caches, disabled bytecode writes and restored the file in `finally`. It is not a
committed correction, viewport-lifecycle proof or approval of a future patch.
