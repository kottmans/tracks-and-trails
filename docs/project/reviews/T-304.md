### Reproduction and controls

The reviewer built a real `FormatTable` from the committed
`derived_format_columns` capture, dressed the application through `theme.apply`,
and clicked the center of header section 0 using `QTest.mouseClick(header.viewport(),
LeftButton, pos=...)`. Positive controls asserted `header.hasFocus()` and
`header.property('focusRing') is False`. Rendering the header and counting the
applied theme's accent pixels gave:

| Palette | After pointer click | After Shift on the same header | Expected pointer result |
|---|---:|---:|---:|
| Light | 430 | 430 | 0 |
| Dark | 430 | 430 | 0 |

The fixed-input scratch regression failed **2 of 2 cases in 0.34s** on exact-head
source. As a diagnostic control only, requiring `self.property(theme.FOCUS_RING_PROPERTY)
is True` in that painter's existing condition changed the renders to **0 after click,
430 after key**, in both themes: **2 passed in 0.50s**. That control changed only a
temporary archived source file, asserted its replacement applied, cleared bytecode
caches, disabled bytecode writes and restored the file in `finally`. It is not a
committed correction, viewport-lifecycle proof or approval of a future patch.

## 2026-10-27 — Focused correction verification

**Reviewer:** Codex, independent of the implementer. **Round:** Focused re-review.
**Correction base/head:** `a3214b2` → `ecdda31`.
**Evidence/check tree:** `a3705e4`; the two changed source files and focus test module
are byte-identical to `ecdda31`. The later task entry supplies the native Windows
observations; those are distinguished from independently run Linux checks below.
**Verdict:** **Approved with follow-ups.** T304-R1 is Resolved. The pre-existing
native Windows focus/geometry questions are scheduled as T-366 before the release
gate, without accepting their risk or declaring the current Windows UI ready.

| ID | Severity | Blocks approval | Disposition and evidence |
|---|---|---|---|
| T304-R1 | Medium | No — resolved | The custom painter now uses `shows_ring`, matching the stylesheet's focus/property condition. The real-click regression verifies no header ring after a viewport click and a ring after Shift in both themes; the viewport-paint counter verifies actual event-loop repainting. Restoring `hasFocus()` alone independently fails 4 tests. The sibling native-drawing route is covered by the proxy style and spin-box regression. |
| T304-R2 | Medium | No — separate follow-up | Open, T-366: reported Windows 10 `windowsvista` keyboard-focus measurements fall below the existing floor on spin boxes, including the bare native-style control outside the wrapper. The pointer half passes. This establishes an outstanding native product-or-instrument question, not a demonstrated regression introduced by this correction. Diagnose and correct the boundary before claiming the release's keyboard/focus checks pass. |
| T304-R3 | Medium | No — separate follow-up | Open, T-366: the same native run reports the format table's stated width 2–3 pixels short and its height one pixel short at 9, 10 and 11 pt. The offscreen passes do not establish the native size contract. This is the pre-existing T-310 geometry surface, outside the pointer-focus correction. |

The full correction diff was inspected. `_KeyboardFocusStyle` changes drawing
options only, withholds `State_HasFocus` while the pointer has the turn, and restores
the original flag in `finally` for all three drawing entry points. It asks the
tracker rather than calling `focusProxy()` from inside a draw. The style is installed
once with the application-owned tracker. The retained scroll-bar lifetime test
checks the observed PySide ownership hazard; the repaint test does not rely on
`render()` forcing a fresh paint. No widget deletion or layout change was established
in the independent checks.

The default-dialog-button exemption is appropriately limited to Qt's actual
`isDefault()` state: its pre-existing fill communicates the Enter action, while the
keyboard must still add a ring. This does not exempt headers or native spin boxes
from the pointer rule. No change to that fill is requested.
