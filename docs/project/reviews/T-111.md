## 2026-08-08 — T-111 implementation review

**Reviewer:** Codex

**Review base:** `c5997fd`
**Review head:** `bf30d82`
**Scope:** the four-commit T-111 boundary, its six acceptance criteria, and the already-reviewed
ARC-008 preset reader needed to judge criterion 6. The untracked handoff
`ai/handoffs/2026-08-08-T-111.md` was read but is not part of the reviewed boundary.

**Verdict:** **Changes requested.** The stored operations, resolved default, ffmpeg predicate, and
basic manager surface work, but saved presets cannot be edited through the shared options screen
P-3/P-16 requires; hand-edited name collisions are accepted unchanged and make name-addressed rows
ambiguous; and the only *Manage presets…* route opens a modal dialog synchronously from Qt's
`commitData` stack, repeating a lifecycle ordering this module already documents as unsafe.

### Review judgments

- **Criterion 3 may use two policies.** Refusing a user-typed collision and disambiguating a name
  generated by Duplicate is a coherent reading of *"refused or disambiguated"*. `T111-R2` is not
  asking for one policy everywhere; it is about the load path applying neither.
- **Criterion 6 is legitimately distributed across tasks.** T-109's reviewed `_presets_from`
  supplies per-entry drop-and-report, and this boundary adds the corresponding `default_preset`
  report. The criterion may be judged across the codebase; the new collision gap is separately
  captured by `T111-R2`.
- **The built-in Delete behavior is not a finding.** The enabled button's silent no-op is unusual,
  but it transcribes the current §8 clause and the row is visibly marked built-in. Revisiting that
  derived clause needs a product ruling, not a reviewer substituting a different interaction.
- **The placeholder is inert for the question asked.** `DownloadManager.requires_ffmpeg` builds no
  worker and `ytdlp_adapter.requires_ffmpeg` reads only `build_postprocessors(request)`; URL and
  output directory do not participate. The reserved `.invalid` URL is not an outbound request.
- **`default_preset_of` is total under REQ-006's non-empty built-in registry.** Missing, deleted,
  empty, and invalid stored names resolve to the first built-in, and the add-dialog wiring consumes
  that resolved name.
