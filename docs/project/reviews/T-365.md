### Containment judgment

The correction addresses both measured ways yt-dlp rewrote an already contained name.
Including environment expansion is appropriate: it crosses the same path boundary as the
Windows directory rewrite, and can silently change the final name even when the claim succeeds.

Inspected the exact installed upstream `_outtmpl_expandpath` and `get_output_path` implementations.
The first expands environment variables before template substitution; the second sanitizes the
whole joined path. The instance wrappers preserve only the worker's staging prefix, including its
escaped percent spelling before substitution. They retain sanitization below that directory and
delegate unrelated paths/templates. The separator in the prefix prevents a similarly named
sibling from matching. `--paths` remains refused, so an upstream directory prefix cannot precede
this literal. The download pass alone installs the wrappers; the probe still renders the user's
template normally. No process-wide yt-dlp monkeypatch is introduced.

The existing tests establish the baseline rewrite as a positive control, then check both wrapper
paths, sections, percent escapes, unrelated paths and real local downloads. ASCII trailing dots
and spaces remain the explicitly excluded Windows path form. No source correction is requested.
