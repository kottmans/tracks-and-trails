### Focused reproduction evidence

These reviewer probes used the shipping implementation with no source or test mutation.
Scratch instruments and logs were kept under `/tmp`; the essential inputs and results are
captured here so the record does not depend on a handoff or temporary file.

**R1 — original slots and actual queued URLs.** Project this synthetic flat extraction with
the real `project_media(..., reachable=lambda _: False)`:

```text
_type: playlist
webpage_url: https://example.invalid/list
title: Example
playlist_count: 3
entries:
  {url: https://example.invalid/a, title: A}
  null
  {url: https://example.invalid/c, title: C}
```

The result reports `entry_count=3` and carries two available entries. Compare
`PlaylistSelection.by_rule(len(media.entries), text, None)` with yt-dlp's actual
`PlaylistEntries(None, raw)`, indexed by `parse_playlist_items(text)`:

| `-I` text | Application's selected available URLs | yt-dlp's selected available URLs |
|---|---|---|
| `1` | A | A |
| `2` | C | None |
| `3` | None | C |
| `-2` | A | None |
| `-1` | C | C |

The reviewer also reused `tests/ui/test_add_dialog.py`'s real-process fixtures and
`_staged_playlist()` helper with a saved preset whose `playlist_items="2"`. Delivering the
real projection of that entry sequence through `_on_media_probed(row.job_id, media)` and calling
`add_to_queue()` gives:

```text
Original slots: A, unavailable, C
Projected entries: ['https://example.invalid/a', 'https://example.invalid/c']
Preset -I: 2
Checked indices: [1]
Queued URLs: ['https://example.invalid/c']
assert queued == []: FAILED
1 failed in 3.06s
```

This proves the defect reaches the queue, beyond a standalone range calculation. The sink
is the existing `FakeSink`; no external URL was downloaded. This is a new interaction with
T-281's legitimate unavailable-entry omission, not a request to undo that omission.
Correction coverage needs holes at the beginning, middle and end, including real
missing-title placeholders, positive/negative indices, ranges and *at most N*. Preserve
the distinction between reported counts and the extraction's original enumerated slots.

**R2 — validation and settings.** For a fresh `OptionsDialog(BEST_VIDEO)`, set the named
`QLineEdit` and call `accept()` before the 400-ms typing pause expires. Read its OK button
and `selection_refusals_text()` afterward:

```text
Uploaded on or after = today-1000000days
  OverflowError: date value out of range; OK=True; refusal=''
Playlist items = '9' repeated 5000 times
  Accepted (result=1); OK=True; refusal=''
Playlist items = '1:3:' followed by '9' repeated 5000 times
  ValueError: Exceeds the limit (4300 digits) for integer string conversion
  OK=True; refusal=''
items_problem('9' * 5000): None
list(PlaylistEntries.parse_playlist_items('9' * 5000)): ValueError
```

The corresponding TOML load probe contains exactly one `[[preset]]` with `name="Hand
edited"`, `format_selector="best"`, `media_kind="video"` and
`uploaded_after="today-1000000days"`. `settings.load(path)` raises the same `OverflowError`
instead of returning its normal `SettingsProblem`. The settings path and dialog probes
were independently executed, not inferred from the exception type alone. Test neighboring
valid values as controls and use specific deterministic-error handling rather than a broad
exception catch that conceals programming errors.

**R3 — model-valid editor inputs.** `dataclasses.replace(BEST_VIDEO, ...)` succeeds for
each row; constructing `OptionsDialog(preset)` then gives:

| Minimum bytes | Maximum bytes | At most | Actual opening result |
|---|---|---|---|
| 1 | 3,221,225,472 | None | `OverflowError` at maximum-size `setValue` |
| 1500 | 2,147,483,648 | None | `OverflowError` at maximum-size `setValue` |
| None | None | 2,147,483,648 | `OverflowError` at at-most `setValue` |

PySide emits its signed-32-bit overflow warning before raising. The second size pair is
already used by `test_a_preset_s_rule_and_filters_survive_a_save`; that test verifies
persistence but never opens the resulting preset. Add the missing composition check.

**R4 — bounded range probe.** Separate subprocesses import `PlaylistSelection`, print
`entered by_rule`, then time `PlaylistSelection.by_rule(3, text, 1)`. A parent timeout of
one second kills each child cleanly; interpreter startup is excluded by the entry marker:

```text
1:3                         returned checked={0} in 0.000119 seconds
-1000000000:3                entered by_rule; TIMEOUT after 1 second
1000000000:1:-1              entered by_rule; TIMEOUT after 1 second
3:-1000000000:-1             entered by_rule; TIMEOUT after 1 second
```

All three failing texts also parse immediately to slices with yt-dlp's real
`parse_playlist_items()`. The last case visits the in-bounds entries and then continues
walking nearly a billion positions below the playlist. Copying an upstream unbounded walk
does not meet this application's GUI-thread budget when the finite count is already known.

### Design assessment and remaining changed surfaces

The complete bounded 30-file change was reviewed against REQ-030/031, the accepted
2026-10-11 ARC-010 and UX-015 amendments, UX_SPEC §6, the task's four rulings and the
architecture's layer/frozen-request rules. The per-job filter mapping, probe isolation,
UTC date freezing, retry preservation and Cancelled outcomes have appropriate direct
tests. The eight typed-versus-CLI filter cases compare the actual `build_options()` output
with `parse_options()`; the seven new integration tests exercise real yt-dlp locally.
Preset-rule changes reach refresh/re-seeding, and unchanged rules preserve manual choices.
The disabled single-video controls preserve preset expansion fields. The JSON default
loading check supports the accepted no-migration ruling.

The two submitted departures cannot be approved in their current form. The shared size
unit loses valid combinations and is addressed by R3; a visible screen-reader label is
also possible for each independent unit control. A core transcription can respect layering
and serve both preset validation and expansion, but the present equivalence tests miss
deterministic parser rejection and the original-slot semantics in R1/R2. Correcting those
must establish the promised yt-dlp behavior; simply adding more normal grammar examples
does not do so.

The crossed-date split is sound for **valid individual dates**: the editor refuses a window
already crossed today, while a persisted preset may age into a crossed window and its
queued request remains representable. The worker reports that empty window as Cancelled
before constructing `DateRange`, and the probe remains unfiltered. R2 concerns invalid
individual dates, not this intentional split.

Moving the hatch's *together* message tests to a stand-in is reasonable here: a separate
test still executes the real whole-line parser check on the now-typed contradictory date
pair, while the seam tests naming and redaction. The real filter-skip integration coverage
was moved to typed requests, and the remaining hatch examples still exercise their
intended scanner and redaction behaviors. The audit/generator changes and 28/37 partition
agree with the model and parser; no additional finding was established there.
