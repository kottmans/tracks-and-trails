### Workflow boundary

The tag-only trigger, read-only default token, `contents: write` restricted to the
draft job, version check before builds, main-ancestry check, checksums, changelog
extraction and explicit `--draft` agree with the intended trust boundary. The
post-creation `isDraft` assertion detects a wrong result; it is not a rollback if
a future edit publishes first. There is no present publish action in this source.

Inno's [OutputDir documentation](https://jrsoftware.org/ishelp/topic_setup_outputdir.htm)
confirms that the configured output directory controls the generated installer.
The preprocessor `SourceDir` define used for `[Files]` is not an output override.
The documented compile output independently confirms the mismatch.

The existing workflow tests pass but check for probe strings and generic artifact
collection; they do not connect the `.iss` output to the Windows upload pattern.
The release-version archive test also passes; that cannot execute this workflow.

### T-319 limits

The `_MEIPASS` ffmpeg correction matches the recorded PyInstaller 6 layout. The
spec preserves `freeze_support`, uses one analysis, adds Windows metadata and
sets `console=False` for release mode. No new source defect was established in
those changes. T-319 is **not approved as complete**: the per-push frozen job still
builds only smoke mode, the no-console HWND assertion and deleted-binary
degradation evidence are unfinished, and DEVELOPMENT does not yet document both
build modes. The green frozen Windows CI job is smoke-build evidence only.

T-324's end-to-end draft criterion remains unexecuted. Its test-branch wording
also needs to agree with the intentional main-ancestry requirement before the
maintainer exercises it. Neither this review nor a passing source test authorizes
tag creation or publication. [Shared checks](phase-5-second-batch.md).
