### Lifecycle reproduction

A fresh SettingsDialog with the normal update/revert callbacks starts with
`Get a newer yt-dlp`. Calling its public busy API with True then False leaves
an enabled button reading `Update to the latest version`.

A second probe opened Settings through MainWindow with a local YtdlpService
subclass whose refresh emits the real busy/report signals without network
or a child process. The same final-label assertion fails. Production
`YtdlpService._on_resolved` and `_on_failed` both call `_set_busy(False)`,
and MainWindow forwards `busy_changed` to the open screen. Thus the trigger
is an ordinary opening check as well as the end of an explicit operation.
The two probes returned **1 failed** each, at the old-label comparison.

### What passes

The accepted OPS-002 amendment and the recorded “demote it and say when”
ruling are respected by the placement, explanatory note and fill change.
The resolved version remains visible and revert remains one action. Error
guidance still provides one appropriate next step, with no update offer for
disk/authentication failures or invented advice for DRM/geo restrictions.
Adding an update offer to DISK in an isolated process fails the new taxonomy
guard: **1 failed**, naming both disk and extractor_error as offered kinds.
No automatic update or new outbound operation was introduced.

Independent Qt rendering probes in both palettes verify different normal
fills for update and revert, the same defined hover fill, normal enabled
text colour, and working update/revert callbacks. **2 passed**. Replacing
only the quiet fill with the ordinary surface produces **2 failed, 1
passed**: both rendering probes fail and the committed presentation test
still passes, establishing R2 without disputing the current appearance.

The rejected muted-text attempt was also checked independently. Adding
`color: muted` to the quiet selector makes the existing colour-classification
guard fail in both palettes: **2 failed**. The implementation did not add
the selector to SECONDARY_EMPHASIS_SELECTORS. Keeping enabled text and
changing fill is a sound choice; a whitelist entry would have changed the
guard's premise rather than supplied rendering evidence.
