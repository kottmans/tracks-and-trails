### Design judgments

The one-value address model prevents the old last-flag-wins conflict. Restricting the specific
address field to IP literals is reasonable: it says which local address to bind, supports both
families and scoped IPv6, and avoids yt-dlp choosing a hostname's family from colon presence.
The refusal is explicit; the equivalent resolved local IP remains selectable.

The one-hour ceiling is an acceptable bounded Settings guardrail, consistent with the existing
connection controls and reported when a file value is clamped. It is an engineering bound, not
a measured network limit. Tenths are a reasonable display precision, provided the model and
reader actually enforce it. Neither judgment approves losing the zero-based random choice.

Leaving a validated local IP readable is consistent with the current credential/cookie-path
rules: it is not an authentication value, and no accepted decision classifies it as secret.
That conclusion is confined to this typed field, not unclassified hatch values.

The new stage follows yt-dlp's actual line, does not introduce an application sleep, and returns
to download progress afterward. Manager accounting, live-stage checks, chips and detail text
all include Waiting. Per-file timing and independent concurrent jobs are explained at the control.
Existing cancellation escalation during an upstream sleep is unchanged, as mapped and ruled.
