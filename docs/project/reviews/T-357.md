### Independent archive checks

The [upstream retention policy](https://github.com/BtbN/FFmpeg-Builds#release-retention-policy)
keeps each month's final build for two years and daily builds for a shorter period. September's
month-end tag is an appropriate bounded replacement; neither the comment nor this review
promises permanent availability.

The [release API](https://api.github.com/repos/BtbN/FFmpeg-Builds/releases/tags/autobuild-2026-09-30-13-08)
independently reports the named asset as 76,972,461 bytes with digest
`sha256:7157177b8a6cb2174c1650ba8c71b363f2c78cba5330f88c4c02cf5b2b880646`.
The production fetcher, with `VENDOR` redirected to a new `/tmp` directory, downloaded the
archive, verified that digest, accepted the licence and returned **0**.

The archived `LICENSE.txt` matches the committed `ffmpeg-LGPL.txt` **byte for byte**, 7,651
bytes. Extraction produced `ffmpeg.exe`, `ffprobe.exe` and seven DLLs. Their names and ABI
suffixes match the cached prior archive; that comparison does not prove runtime compatibility.

Independent reads of NUL-terminated configure strings in `ffmpeg.exe` and `avutil-61.dll`
found `--enable-shared`, `--disable-static` and `--enable-version3`, with neither
`--enable-gpl` nor `--enable-nonfree`. The avutil binary contains `LGPL version 3 or later`.
The pin therefore preserves the reviewed shared LGPL build choice and unchanged licence text
required by `LIC-001`. Packaging tests passed in the unit/UI run.
