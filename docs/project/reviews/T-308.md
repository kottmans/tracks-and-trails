### T-308 — what the independent launch establishes

Ran the real `app.run()` entry point in a separate offscreen process. All three
XDG roots pointed to an isolated temporary profile containing valid settings with
a nonexistent download folder and concurrency 7. A `MainWindow` subclass observed
the real show event and delegated warning creation to the unchanged production
method. Its event-loop callback checked the warning and closed the application
through the normal window-close path. Observed:

```text
ORDER ['window.show', 'settings.report']
PASS actual run: visible warning; shown parent; native transient parent
exit status 0
```

The warning was unique, visible, parented to the shown main window, and its
`QWindow.transientParent()` was that window's handle. It used `open()`, preserving
the existing asynchronous modal behavior. The printed summary correctly described
the missing-folder case. “Native transient parent” in the captured probe output
means the Qt window-handle relationship under the **offscreen plugin**; it is not
native compositor evidence. No real-display stacking result is inferred.

To attack the regression coverage, copied the package to a temporary directory,
removed only the following production branch from the copy, and confirmed imports
resolved to the copied `app.py` through `PYTHONPATH`:

```text
if composition.settings_problem is not None:
    composition.window.report_settings_problem(composition.settings_problem)
```

Ran the repository's unchanged tests with that copy first on `PYTHONPATH`:

```text
pytest -q tests/integration/test_composition.py -k 'settings_problem or corrupt_settings or stored_ffmpeg or unusable_stored_template'
7 passed, 68 deselected in 0.80s
```

This surviving mutation supports R2. It does not invalidate the passing current
launch probe or establish a native stacking failure. The new guard does check that
`compose()` no longer opens the settings box. The gap is the subsequent production
call, which the helper supplies on the test's behalf.

### T-309 — classification and counterexamples

The boolean is adequate for the specific question “could the file be read?” All
production constructors were inspected: parse/read failures retain `True`,
successful loads with warnings set `False`, and `_joined` preserves the existing
value or uses `False` for an added non-read warning. Independent probes confirmed
the three join cases (`None → False`, `True → True`, `False → False`). A valid
missing-folder file retained concurrency 7 and a dark theme; a genuine malformed
file retained the read-failure headline. The discarded missing-folder path is now
labelled as the stored value rather than appearing to name the destination.

The additional inference “readable warning → defaults” is what fails. Reproduce
R1 from the repository environment by writing either of these valid files and
calling `tracks_and_trails.core.settings.load(path)`:

| TOML | `Settings().network` default | Loaded effective value | Reason in the same warning |
|---|---|---|---|
| `[network]` followed by `rate_limit_bytes = 1` | `rate_limit_bytes=None` (no limit) | `rate_limit_bytes=1024` | `1024 bytes per second is in use.` |
| `[network]` followed by `retries = 999999` | `retries=None` (downloader default) | `retries=100` | `100 is in use.` |

Both loads set `problem.unreadable=False` and leave the file content unchanged.
Both emit the same first line:

```text
Some of your settings could not be used, so their defaults are in use. The rest of the file is unchanged.
```

For R2, used the exact new fixture's string construction with
`PureWindowsPath('C:/Users/Reviewer/AppData/Local/Temp/test')` as the directory
prefix, wrote the resulting text to a real temporary file, and called `load`:

```text
Windows fixture unreadable: True
Invalid hex value (at line 7, column 18)
```

Also invoked the actual new test function with a small path adapter returning a
real temporary `settings.toml` target and that Windows-form `gone` path. It failed
at its intended readable-file assertion:

```text
AssertionError: the file was read; only a value fell back
```

This isolates TOML encoding from Windows filesystem behavior. The fixture needs
to express the path correctly before it can test T-309 on Windows; Linux passing
and Windows-platform static typing do not exercise this string representation.
