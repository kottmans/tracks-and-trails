### Certificate correction

The implementation injects truststore in the application before probes and in
each spawned worker before yt-dlp is resolved. The context-construction tests
exercise yt-dlp and urllib, and the worker test checks a fresh interpreter. This
matches truststore's [application integration guidance](https://truststore.readthedocs.io/en/latest/).
The added MIT text matches the installed dependency and is required by the gate.
Linux keeps its system-store behavior. No bypass of certificate verification was
introduced.

The causal claim should remain bounded: an absent named root plus a successful
Windows request does not establish the precise chain Windows built. That does
not invalidate the approved choice of native verification. The missing retained
fixed-artifact run is T318-R1, not proof that the correction fails.
