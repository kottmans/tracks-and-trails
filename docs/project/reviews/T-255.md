### Generator and merge judgments

The generated allowlist is a suitable boundary at the pin. Inspected the upstream reader's
default `self.ie_key()` behavior and the generator's explicit key, class and provider resolution.
An unnamed read in an inherited method can use the real subclass's key, so walking the real
descendants is appropriate. An independent probe forced the 1,751 extractor class modules to
load before regenerating: the result stayed **27 keys, 68 pairs**, independent of that import
order. A synthetic inherited read resolved under the descendant key; an unknown dynamic read
was reported unresolved. `rendered` stops on that unresolved list.

Checked all three manual answers at the actual source: HotStar's `_IGNORE_MAP`, TikTok's
`_APP_INFO_DEFAULTS` excluding `iid`, and the YouTube local lambda's sole `comment_sort` call.
They are correct at this pin. They remain explicit assumptions to revisit when updating the
upstream source; regenerating a table is not a semantic proof of arbitrary changed call graphs.
The provider and `youtube-ejs` namespaces are genuine reads, including keys that are not extractors.

The six forbidden pairs match the accepted SEC-003 amendment and are refused regardless of value.
The editor checks text and gates both the button and `accept`; the model independently validates
the held structure. Values stay out of the request, preset and format-choice reprs. Both passes
receive the arguments, and the manager registers classified secrets in the parent before the
worker starts. R1 and R3 identify the paths this otherwise sound registration does not protect.

Merging repeated lines by key and argument, with the later value for the same argument winning,
is the approved correction to silently dropping the earlier line. It is deliberately different
from yt-dlp's repeated-option parser, and the normalized editor makes that behavior visible.
Ignoring a stray semicolon while refusing an empty argument line is reasonable; losing a valid
argument during subsequent display is not covered by that judgment.
