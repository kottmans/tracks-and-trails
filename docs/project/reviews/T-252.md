### R1: controlled real-download evidence

The scratch regression reuses the committed six-second test clip, real worker,
generic extractor and local HTTP handler. For the conventional-MP4 case, ffmpeg
remuxes the valid clip with `-c copy` and default output flags; a positive control
checks `moov` follows `mdat`. An uncut download of that same served source contains
**two streams and six seconds**. Every case restores its source bytes, so the
faststart cases do not inherit the conventional-MP4 mutation.

| Requested download | Actual successful result at `7aadd3d` |
|---|---|
| Conventional MP4, `*1-3`, server without ranges | `Clip.mp4`, **262 bytes**, **0 streams**, no duration |
| Fresh faststart MP4, `*99-100` | `Clip.mp4`, **142,333 bytes**, **2 streams**, **6.000000 s** |
| Fresh faststart MP4, `*0-2` and `*99-100` | Section 1: **2.020000 s**; section 2: the **6.000000 s full source**; overall Succeeded |
| Positive faststart control, `*1-3` | **2 streams**, **2.019002 s**, as requested |

The fixed-input regression requires media streams for successful cuts, rejects
success with an impossible range, and checks the positive control's duration.
**3 failed, 1 passed in 4.94s.** Paths and media are entirely temporary. The outcome
is the worker's actual Succeeded message; ffprobe independently reads each artifact.
No live external site or Windows behavior is inferred.

An initial exploratory batch reused the module-scoped modified clip and was
superseded by the isolated-source runs above. A stream-presence-only intermediate
probe caught the empty file but also exposed whole-source substitution; the final
regression checks both consequences. The finding relies on the controlled final
results, not the superseded batch.
