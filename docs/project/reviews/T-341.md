explicitly selected trust configuration. Existing default locations are likewise preserved.

the system store; it does not require an external user report in that case. Fedora establishes
that condition. Finding the same system store is a mechanism correction within the accepted
trust choice; it does not adopt the previously rejected bundled-certifi alternative.

Independent boundary probe: with no user overrides and an available valid one-certificate bundle,
a README-only default directory and an empty default file both leave the environment unchanged.
`openssl verify` against that README-only directory fails (exit 2); using the available bundle
passes (exit 0). Thus presence is not certificate validity. Conversely, simply testing a fresh
context's certificate count would also be insufficient for a legitimate directory store:
[OpenSSL loads hashed CA-directory entries when verification needs them](https://docs.openssl.org/3.0/man3/SSL_CTX_load_verify_locations/).
Do not turn this Low naming correction into an assumption that every directory must eagerly load
certificates at startup.

The existing unit cases cover first existing bundle, empty directory, pre-existing file/directory,
both user overrides, no bundle, and real OpenSSL loading one certificate after the environment
change. Independently disabling the fallback write makes **3 tests fail**; the remaining **10 pass**.
