The new window hosts the existing LogView, opens nonmodally, has a plain-text title, focuses its
read-only text, and closes through Escape or Close. Qt parent ownership and delete-on-close
bound its lifetime. Copy rereads the complete current log file, rather than copying only the
bounded rendered tail. The queue handler rereads the current job before opening; a vanished row
therefore does not open an unrelated log. New routes retain the existing logging/redaction boundary.

Both placement choices are sound within the existing requirements and accepted design:

- The queue overflow and right-click/keyboard menus share the entry. Including it even when no
  ordinary verb was dropped makes the maintainer's chosen overflow route useful on a wide row;
  keyboard access follows NFR-005. The action is absent without recorded bytes.
- Failed Add-dialog lines need the same access. UX-003 deliberately keeps unsuccessful probes in
  the dialog rather than persisting them as queue jobs. The manager still has a classified failed
  staging job and its own log. That is the appropriate place to satisfy criterion 6's visible
  extractor error and copyable diagnostics under the accepted staging design. It does not require
  inserting an uncommitted failed probe into the durable download queue. The remaining human check
  must show the actual error, successful copy and an unaffected companion download.

The added tests exercise both queue menus, wide overflow, missing/empty files, a failed Add line
logged through the real worker-to-parent logging route, a silent failure, a successful line, and
window modality/title/focus/closing. These source assertions are accompanied by the complete
local and exact-candidate Windows CI results in the shared review.

Independently disabling `main_window.has_job_log` causes **both** queue-route regressions to fail.
The first instrument changed only `log_view.has_job_log`, after the caller had already imported
its reference; both tests passed because that mutation did not reach the call site. That run is
discarded as an instrument error, not counted as proof or concealed as a successful mutation.
The corrected caller mutation produces the expected two failures. The remaining submitted
mutation cases were inspected but not freshly executed by Codex.

**Log timing limit:** log and result messages use separate queues. A failure can become visible
before its final log line is written, and the added test explicitly waits for that line before
opening the menu. Diagnostics reads a snapshot when opened; it has no drain notification or live
refresh. Copy rereads the current file, and reopening reads a fresh snapshot. Thus the evidence
establishes reachability and copying once bytes arrive, not an atomic guarantee that opening
immediately on failure already displays the last line. The existing drain protocol preserves the
file's eventual tail; no new logging-loss defect was established here. This limitation is not
promoted into a completed manual acceptance result.

placement interpretations separately. Existing decision text remains intact. No desktop session
