### Implementation and regression assessment

The reviewed behavioral change is `encoding="utf-8"` on `_formatted`'s text-mode
`subprocess.run`. It fixes both the bytes written to Ruff and decoding of Ruff's response.
The argv, generated module and inventory semantics are unchanged.

The regression reaches the production `_formatted` function in a new interpreter with
`PYTHONUTF8=0`, `PYTHONCOERCECLOCALE=0` and `LC_ALL=C`. Its source argument uses `!a`, and its
stdout uses an explicitly encoded byte buffer. Thus the em dash crosses the formatter pipe
without relying on decoding the child's command line or encoding its console output.
It is a meaningful behavioral test rather than an assertion that a keyword is present.

An independent negative control removed only `encoding` from that call's arguments in the
child process, without editing repository source. It exited 1 with `UnicodeEncodeError` from
the ASCII pipe encoding. Production code passes the same forced-locale test. This proves the
test detects the original class on Linux; it does not claim cp1252 was exercised on Windows.
