### T310-R1 — Required notes are no longer reachable

`src/tracks_and_trails/ui/format_table.py:258` and `:272` declare the production
column sets. Neither contains `NOTES_COLUMN`. With a nonempty `FormatInfo.note`,
both live models return **-1** from `column_for(NOTES_COLUMN)`; no other live cell
or tooltip exposes that note. `_text` still supports notes at line 751, so tests
of the default, full-column `FormatTableModel` pass while the application loses
the field. This affects all notes, not just the redundant “video only” label.

Restore notes where supplied and verify representative Video and Sound entries
through `FormatTable.lists()`. REQ-003 and UX_SPEC §4 explicitly retain notes;
the two-list ruling does not remove them.

### T310-R3 — A valid change of choice becomes unavailable

`format_table.py:1457` calls `set_dimmed` whenever `_picked_whole` exists, although
`choose` already supports replacing that selection with an audio-only format.
Using `derived_format_columns`, selected a Video row and clicked the real Sound
button with `QTest.mouseClick`:

| First selection | Attempted Sound selection | Result |
|---|---|---|
| Complete format `2` | `140` | Selector stays `2`; Sound view and button disabled |
| Unclassified `h264-hd` | `140` | Selector stays `h264-hd`; same disabled state |

Both buttons say **“That format has sound already”**, which is not established
for the second entry. Users can work around this by reopening the panel or
first choosing a video-only entry when one exists. This is a narrow transition
failure, hence Medium, but it violates the task's no-refused-selection behavior.

The approved layout mockup also dims this list; that explains the implementation
but does not reconcile it with the recorded selection contract. An audio-only
replacement need not merge sound into the whole format. Keep that replacement
reachable, with wording that describes its actual effect. Test real input after
both COMPLETE and UNKNOWN choices: `test_no_choice_is_ever_refused` at line 1647
currently traverses only the Video list, and direct `table.choose(audio)` bypasses
the disabled controls.

### T310-R4 — Esc leaves an abandoned merge active

`add_dialog.py:1820` snapshots only `row.preset`; `_on_selection_changed` at
line 2278 writes both the preset and `row.format_selection`. With
`_staged(..., ffmpeg_available=False)`, start with both fields `None`, open the
panel, choose `137`, then `140`, and press Esc on the panel. The panel closes and
the preset returns to `None`, but `format_selection` remains PAIR(`137`, `140`).
Calling Add submits **no job** and reports that merging needs ffmpeg. Before
the edit, `_merge_refusals([row])` returned `None`.

The new behavior makes this route reachable: a finished pair now stays open and
can be abandoned, and absent ffmpeg no longer removes the selection route.
The existing Esc test chooses only one video and checks only preset identity.
Restore the prior selection object as well as the preset, including when the
prior choice was itself a pair. Assert the resulting Add/refusal behavior.
Audit the sibling preset replacement in `StagingModel.setData` at line 1211,
which also writes the preset independently of the stored selection.

### T310-R5 — Bundled audio loses its raw codec

`format_table.py:722` handles only `VIDEO_CODEC_COLUMN` and `AUDIO_CODEC_COLUMN`
for raw tooltips. The live Video list now renders the audio codec in
`SOUND_COLUMN`, so a complete entry with `audio_codec="mp4a.40.5"` displays
**“included · HE-AAC”** and returns **None** for ToolTipRole. The raw identifier
is unavailable from that row. UX_SPEC §4 explicitly retains T-306's raw-codec
tooltip behavior.

Handle the live Sound field and assert the exact raw literal independently of
`codec_name`. Cover the actual list model; full-model audio-column tests cannot
detect this remapping regression.

### T310-R6 — A known audio codec is treated as no information

`format_table.py:157` checks only height and video codec for an UNKNOWN entry.
Feed `project_media` a format with `format_id="known-audio"`, `ext="mp4"`,
`acodec="aac"`, a media URL, and no `vcodec`, size, bitrate or dimensions. The
projection is `has_video=None`, `has_audio=True`, `audio_codec="aac"`.
`says_nothing` nevertheless returns **True**. Beside a second format reporting
`vcodec="h264"` and `height=720`, `video_formats` returns only the second entry.

This is a synthetic adapter-input counterexample, not a claim of a freshly
observed site failure. It satisfies neither recorded exclusion: both streams
were not denied, and a codec was supplied. Preserve that information without
guessing that unknown video means absent video. Check partially known fields
alongside the wholly unknown and explicitly absent variants already covered.
