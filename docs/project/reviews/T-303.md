### Scope and findings

Reviewed the T-303 task, `4a7db8e`'s theme and focus-test changes, and their
integration at the stated head against NFR-005 and TESTING §14. No actionable
finding. T-304's mouse-versus-keyboard focus policy is separately ruled and
unimplemented; this approval does not cover it. T-305 and T-306 have separate
review records and verdicts.

The transparent idle border and generated focus selector reserve the same two
pixels for both control classes. The existing inventory, focus visibility and
outer-geometry checks cover the expanded inventory; the new sub-element check
covers check box and radio contents. It does not establish automatic coverage
of the internal geometry of every possible future widget class.

In an independent probe, constructed the actual `OptionsDialog(BEST_VIDEO,
subtitle_languages=('en',))`, applied each application theme, showed it, and moved
focus between an enabled button and each enabled check box/radio. Asserted that
the target held focus before comparing `QStyleOptionButton` sub-element rectangles.
All **seven controls in each theme** retained contents `(22, 2, 220, 17)` and
indicator `(2, 3, 14, 14)`. The dialog's measured client size was **302 × 796**.
Toggling the metadata check box also preserved those rectangles.

Visually inspected offscreen renders of the actual dialog's Embed and Container
groups in both themes, including the toggled metadata box: the focus rectangle
was visible and its left edge was complete inside the group. This supplies the
task's by-eye check in the recorded environment. It is a reviewer inspection of
rendered widgets, not a maintainer desktop session or a Phase 4 checklist run.
