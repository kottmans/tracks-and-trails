### Privacy reproduction and controls

The reviewer served an HTML5 page, an MP4 body and an invalid TTML subtitle from
`127.0.0.1`, then called the real `worker.run_session()` with:

- `write_info_json=True`, `subtitle_languages=("en",)`, `retries=0`;
- `--convert-subs srt --add-headers "Authorization: Bearer REVIEW_HEADER"`;
- a Netscape cookie file for `127.0.0.1` carrying the synthetic `REVIEW_COOKIE`.

The page uses `<video><source src="/clip.mp4" type="video/mp4"><track
src="/en.ttml" kind="subtitles" srclang="en"></video>`. The media body is 4,000
zero bytes and the TTML body 64 zero bytes. The generic extractor discovers the
subtitle normally; no extractor or postprocessor was mocked in the failing case.
Admission accepts the options. The session returns `Failed(EXTRACTOR_ERROR)`,
`not well-formed (invalid token): line 1, column 0`. Its
`.tracks-and-trails-staging-…/clip.info.json` still contains **both** synthetic
credential values. A final assertion that neither remains fails (exit 1).

An independent in-memory control moves the newly registered `InfoJsonStripper`
to index 0 of `ydl._pps["before_dl"]`. With the same source and request the session
still fails on the malformed TTML, but the retained JSON contains **neither**
credential and the assertion passes (exit 0). This demonstrates the ordering
defect without changing repository source. It is correction evidence for the
specific trigger, not approval of a complete production fix.

Both existing privacy passes are useful. Independently replacing the hook with
a no-op makes the committed failed-download test fail (**1 failed in 1.74 s**).
Replacing only `worker.strip_kept_info_json` with a no-op makes the committed
replaced-hook success test fail (**1 failed in 1.55 s**). Neither existing test
exercises a processor failing ahead of the hook. Initial probes using plain-text
and zero-filled WebVTT converted to empty SRT successfully and did not reproduce
the defect; malformed TTML supplies the deterministic failing conversion.
