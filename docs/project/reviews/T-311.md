### Reproduction and independent state checks

For R1, used the real staging dialog, its row editor, and the existing
`_pick_a_pair`/`choose_in_editor` helpers from `tests/ui/test_add_dialog.py`:

1. Start with an inheriting resolved row; choose video `137` and audio `140`, then Done.
2. Verify `row.preset is None`; open the row preset editor and choose its `None` entry.
3. The expected `row.format_selection is None` fails; it still names `137+140`.

The existing test `test_following_the_batch_still_gives_up_a_chosen_format`
passes because it deliberately inserts a named-preset selection between steps
1 and 2. This establishes that a route exists, but requires an unrelated
intermediate choice. The finding does not claim that clearing is impossible.

For R2, constructed a real `FormatTable` with these explicit formats:

| ID | Container / codec | Stream flags | Other information |
|---|---|---|---|
| `v` | MP4 | video true, audio false | height 720 |
| `a-low` | Opus / Opus | video false, audio true | note `low`; bitrate and size absent |
| `a-high` | Opus / Opus | video false, audio true | note `high`; bitrate and size absent |

`table.lists()[1].model.column_for(NOTES_COLUMN)` returns **-1**. The
formats are listable because their codec is known. Both audio rows otherwise
say the same thing apart from their IDs. This is a valid model input, not a
claim that a particular captured extractor currently produces it.

The options call site was audited under the new rule. An unchanged accepted
staging Options dialog keeps the pair, creates the explicit row override its
existing contract promises, and subsequent batch changes do not overwrite it.
Choosing the inherited entry from that owned state clears the pair and restores
the batch selector. That sequence passed independently. The template route
likewise derives from `preset_for`; format-panel Esc restores its captured
prior state. Baking an effective selector into an options-derived preset does
not, by itself, establish a user-visible loss in these supported transitions.

The existing guards for preserving naming, media kind, conversion and bitrate,
batch changes, explicit row overrides, Esc, note inventory and compound notes
passed in the full suite. Restoring the pre-T-313 `setData` in an isolated
process fails `test_committing_the_preset_control_unchanged_keeps_the_chosen_formats`
on its named assertion: **1 failed in 1.09s**. Production source was not edited.

### The recurring integration failure

The handoff's pattern is supported by the diffs and remains relevant to the
new findings. T-311 changed what a preset assignment means without reconciling
its old clearing side effect. T-314 connected a control without reconciling
the adjacent control's purpose. T-315 now separates the pointer menu while
leaving the documented keyboard equivalence behind; see [T315-R1](T-314.md).
T-313's clear-route test similarly starts from the state where its guard works,
rather than the inheriting state that motivated the change.

This is an observation, **Note / Blocks approval: No**, rather than a new
process task. The requested corrections already fall under TESTING §14's
sibling-state and call-path audit: exercise the user gesture, its automatic
commit counterpart, both ownership states, and the other consumers of the
shared control. Additions to policy are not needed to perform that audit.
