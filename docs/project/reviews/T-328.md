### T328-R3: independent counterexample and correction boundary

The ordinary-row context menu uses nonmodal `popup()`, so the application's retry timer continues
while it is open. A NETWORK failure may automatically retry and then discover DRM. Updating the
row correctly removes Retry from a newly offered menu, but neither updating the row nor delivering
the failure closes or disables the existing QAction. Group retry separately rechecks each member;
ordinary retry does not.

The deterministic offscreen probe uses the existing `FakeQueue`/`make_job` test helpers, a store
implementing `requeue_at_end`, the real `DownloadManager`, and the real `MainWindow` with
`retry=manager.retry`. Only worker admission is replaced by a recorder to prevent spawning or
network activity. Its sequence is:

1. Store a FAILED/NETWORK job, ask the real queue view for its verbs, and open
   `window._show_row_menu(job.id, offered, True)`. Retain `rowVerb_retry` from that real QMenu.
2. Deliver QUEUED and RUNNING state updates, then FAILED/DRM_PROTECTED, representing the next
   automatic attempt. Emit `job_changed` for each state and `job_failed` for the final failure;
   process Qt events throughout. The old menu remains visible/enabled through every update.
3. Verify the fresh row offers no Retry, activate the retained QAction, and inspect the actual
   manager's persisted transition and admission request. Require the job to stay FAILED with no
   admission. That assertion **fails** at `00c422c`:

```text
Fresh row offers Retry: False
Old menu visible/enabled: True True
After old menu action: queued drm_protected admissions [('stale', <SessionKind.DOWNLOAD: 'download'>)]
AssertionError: stale ordinary-row menu retried a DRM failure through the real manager
```

The same probe with a temporary in-memory wrapper rejecting the current FAILED/DRM job before
calling the manager passes: status remains `failed drm_protected`, admissions `[]`. This control
is diagnostic, not a production correction or evidence that one entry check covers write races.
The first instrument attempt had the wrong signal arity and failed before exercising behavior;
after correcting that instrument, the failing baseline and passing guarded control were both
rerun, including the intervening QUEUED/RUNNING notifications. Logs and scripts are retained in
`/tmp/tt-review-stale-drm-menu{,-guard}.{py,log}` for this session.

No DRM service was contacted, and no media decryption is claimed. The demonstrated defect is
admission of a new attempt after the application already classified the job DRM_PROTECTED,
contrary to SEC-001 and TESTING §7. Workers still check DRM when an attempt executes. That later
check does not satisfy the explicit no-retry/no-bypass-path requirement. Deferring this to 0.1.1
is therefore not approved. The correction must test the actual manager, the old UI action,
non-retryable failure variants and pending writes, and retain ordinary retry and explicit
cancelled-job Queue again positive controls. UI-only refresh is insufficient as the final guard.
