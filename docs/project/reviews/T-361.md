### Assessment

The complete seven-file change fixes the accepted-and-dropped aliases without maintaining
a second hand-written spelling list. `built_spellings()` starts from the audit's explicit
built table, then takes each option's short and long names from yt-dlp's parser. Hatch
admission refuses those names for their existing controls before destination projection
can discard them. The four redaction exemptions removed here belong to options now
refused; the ordinary-value control uses the still-admitted `--socket-timeout 1000`.

The reviewer independently read the **21 built rows at `c7e562b`**, expanded them with
`create_parser()` and obtained **32 spellings**. This agrees exactly with that commit's
generated table. Compared with `dab8fc1`, the added spellings are:

```text
--add-chapters       --add-metadata       --extract-audio
--limit-rate         --no-add-chapters    --no-add-metadata
--no-write-srt       --rate-limit         --retries
--srt-langs          --write-srt
```

The same enumeration, including the parser's top-level options and option groups, finds
**no further spelling sharing a built option's destination**. This independently answers
criterion 3 for the pinned yt-dlp version.

The new regression test derives aliases from the parser and the audit, independently of
both the generated table and the production `built_spellings()` function. As a reviewer
negative control, substituting the old table in memory and walking all 32 independently
derived spellings loses `HAS_A_CONTROL` on **exactly these eleven**. The current table is
restored afterward; no source or tests were edited for this probe.
