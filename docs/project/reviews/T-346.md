### Reproduction and correction evidence

Create a Linux download directory named `<style>downloads`, save an ordinary `clip.mp3`
there, delete it, and activate Show in folder. The independent offscreen probe built
the completed row using the real `safe_output_path(directory, "clip.mp3")`, then invoked
the real queue verb and window notice. The selected root is preserved by path sanitation;
this case does not depend on bypassing the application's filename sanitizer.

For a root `/tmp/example/<style>downloads`, the label says only
`clip.mp3 is no longer in /tmp/example/`, losing the actual directory and the explanation
about moving, renaming or deletion. `QAccessible` reports that same truncated label.
Calling `box.setTextFormat(Qt.TextFormat.PlainText)` in the probe restores the entire
literal message, including `<style>downloads`, without changing `Refusal.reason`.
Ordinary paths work in both modes, and Remove still targets `job-1` in both cases.
Local probe and capture: `/tmp/tt-review-ea49516-ui-probe.py` and its `.log`.

The initial exploratory probe also used a raw filename `<style>clip.mp3`, which hides
the whole explanation. That is not the supported-path reproduction: application filename
sanitation removes those characters. The selected-directory case above establishes the
shippable defect and its narrower Medium severity. It blocks under TESTING §14 because
the notice fails to convey the literal refusal it exists to show.

for the inspected NFR-005 mechanism. The box exposes `AlertMessage`, the title `File not
found`, its explanatory label and standard buttons. OK is the default; removal captures
the acted-on job and uses the existing queue-removal route. An extra announcement is not
needed to replace a missing semantic role here. This is Qt accessibility-tree evidence,
not a claim that Codex heard Narrator or Orca speak the box.
